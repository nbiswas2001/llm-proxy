# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```sh
cargo run -- --config config.toml       # run (config.toml is gitignored; copy config.example.toml)
cargo run -- --check                    # validate config and exit without binding a port
cargo test                              # all tests
cargo test routes_alias_and_rewrites    # a single test by name substring
cargo clippy --all-targets              # kept at zero warnings
cargo fmt
```

`LLM_PROXY_LOG=llm_proxy=debug` logs every forwarded request (provider, URL, model, stream flag).
`--port` / `--host` override the config file. Secrets live in a gitignored `.env`
(`.env.example` is the template); `--env-file` points at a different one.

Rust edition 2024; the code uses let-chains, so it needs a recent stable toolchain.

## Architecture

Three files, one job: accept OpenAI-protocol requests on `:8600`, forward them to a
configured upstream provider with the real API key attached, and stream the response back.

**`src/proxy.rs` — the forwarder.** `proxy()` is registered as the router's `fallback`, not
as a set of endpoint routes. That is deliberate: the proxy never needs to know which OpenAI
endpoint is being called. Any path is forwarded verbatim, so `/v1/embeddings`,
`/v1/responses`, and endpoints that do not exist yet all work without code changes. Only
`/health` and `GET /v1/models` are explicit routes.

The request lifecycle:

1. Client auth (`client_auth_error`) — only enforced when `server.api_keys` is non-empty.
2. Body is read whole and parsed as JSON *only* to read `"model"`. A non-JSON body is
   forwarded untouched.
3. `Config::resolve` picks the provider.
4. If the resolved upstream model name differs from what the client sent, `"model"` is
   rewritten in the JSON body and re-serialized.
5. Headers are copied minus `STRIPPED_REQUEST_HEADERS` + `HOP_BY_HOP`; the client's
   `Authorization` is dropped and replaced with the provider's key. `accept-encoding` is
   stripped so upstream never compresses a stream we relay.
6. The response is re-framed as `Body::from_stream(response.bytes_stream())` — this is what
   makes streaming incremental rather than buffered. Because the body is re-framed,
   `content-length` must be dropped from the response headers (`is_stripped_response_header`).

Errors are returned in OpenAI's `{"error": {...}}` shape via `error_response`. Upstream
status codes and error bodies pass through unchanged; only transport failures become
502/504 generated by the proxy.

**`src/config.rs` — routing policy.** `Config::resolve(model)` decides everything about
where a request goes, and is the part worth reading before changing behavior. Precedence:
explicit `"<provider>:<model>"` prefix → a key in some provider's `model_aliases` →
a name in some provider's `models` → `default_provider` (or the sole provider). The alias
and list passes iterate `ordered_providers()`, which yields the default provider first so it
wins ambiguous names. A colon in a name that is not a configured provider (`"llama3:8b"`)
must fall through rather than be read as a prefix — there is a test pinning this.

`Provider::upstream_url` joins `base_url` with the request path while collapsing a duplicated
version segment (base `.../v1` + path `/v1/chat/completions` must not yield `/v1/v1/...`).

All config structs use `#[serde(deny_unknown_fields)]`, so a typo'd key is a startup error
rather than a silently ignored setting — adding a config option means adding the field.
`expand_env` handles `"${VAR}"` / `"env:VAR"` only as a *whole* string, not interpolated
within one. It resolves against the process environment, which `load_env_file` has already
populated from `.env` (real environment variables win — `dotenvy` does not override). A key
that resolves to empty is a startup error, since an unfilled `.env` line would otherwise
send `Bearer ` upstream and fail as a confusing 401.

**`src/main.rs`** loads `.env` *before* initializing logging — so `LLM_PROXY_LOG` can be set
there too — then wires the CLI, builds the shared `reqwest::Client` (its `timeout` covers a
whole streamed response, hence the 600s default), and constructs `AppState { config, http }`.

## Config file gotcha

`default_provider` is a bare top-level key and must appear **above** the first `[table]`
header in `config.toml`, or TOML parses it as a member of that table and startup fails with
`unknown field 'default_provider'`. `config.example.toml` is ordered correctly.

## Testing

Unit tests live in `#[cfg(test)] mod tests` at the bottom of `src/config.rs` and cover
routing precedence, URL joining, and client auth. There is no integration-test harness; to
verify forwarding and streaming end to end, run a throwaway HTTP server that emits chunked
SSE with a delay between chunks, point a config's `base_url` at it, and check that the
client observes that same delay between chunks (buffering anywhere would collapse them).
